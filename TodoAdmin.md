# TodoAdmin — что нужно добавить в Firebase для полноценной работы панели заказов

Страница `/admin/orders` сейчас работает в режиме «визуал»: статусы заявок, архив и настройки сайта — заглушки. Ниже список изменений на стороне Firebase, чтобы всё заработало по-настоящему.

## 1. Поле `status` у заявок (Firestore)

- В коллекции `orders` добавить каждому документу поле:
  ```
  status: "new" | "in_progress" | "done"
  ```
- Для существующих заявок проставить `status: "new"` вручную через консоль Firestore или разовым скриптом.
- В коде: при создании заявки (`use-order-submit.ts`) писать `status: "new"` — **уже реализовано**.

## 1.1. Номер заказа `orderNumber` (Firestore)

- Код уже пишет поле `orderNumber` формата `#BF-ГГГГ-MMDD-NNN` (NNN — порядковый номер заявки за день).
- Для существующих заявок поля нет — в панели показывается запасной вариант из авто-ID Firestore. При желании проставить номера старым заявкам вручную.

## 1.2. Поле `boatModel` (опционально)

- Карточка заказа выводит «Модель лодки», если у документа есть поле `boatModel`.
- Сейчас форма на сайте это поле не собирает; чтобы данные появились, нужно добавить поле в форму `/order` и писать его в `use-order-submit.ts`.

## 2. Смена статуса из панели

- Правило безопасности должно разрешать авторизованному админу обновлять документы:
  ```
  allow update: if request.auth != null;
  allow delete: if request.auth != null;
  ```
- UI: кнопка «Принять в работу» и дропдаун «Изменить статус» в карточке → `updateDoc(doc(db, "orders", id), { status })` — **уже реализовано** (страница `/admin/orders`).

## 3. Архив заказов

- Архив = заявки со статусом `"done"`.
- Роут `/admin/archive` — **реализован**; на странице активных показываются только заявки без статуса `done` (фильтрация на клиенте, индекс не требуется).
- Запрос: `query(collection(db, "orders"), where("status", "==", "done"))` — при переходе на серверный фильтр.

## 4. Индекс Firestore

- Если добавим сортировку + фильтр (архив по дате), создать составной индекс
  `status ASC, timestamp DESC` — консоль Firestore сама предложит ссылку при первом запросе.

## 5. Настройки сайта (опционально)

- Коллекция `settings` (документ `main`): телефоны, график работы, соцсети и т.д.
- Публичное чтение, запись только авторизованному админу.
- Пункт «Настройки сайта» включить после реализации страницы настроек.

## 6. Правила безопасности (итоговый минимум)

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /orders/{orderId} {
      allow read: if request.auth != null;
      allow create: if true; // заявки с сайта создают неавторизованные
      allow update, delete: if request.auth != null;
    }
    match /settings/{docId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
  }
}
```

> ⚠️ Сейчас правила нужно проверить: запись заявок открыта (иначе форма не работает), а чтение/удаление должны быть только у авторизованного администратора.
